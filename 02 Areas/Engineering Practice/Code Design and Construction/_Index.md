# Code Design and Construction

## Quick Reference

This category covers Readability, Simplicity, Naming, Code Organisation, and more. Published notes and narrower categories are linked below.

## Published Notes

- [[Dependency Inversion Principle|Dependency Inversion Principle]] - Put a stable policy boundary between high-level decisions and volatile implementation details when it reduces change coupling.
- [[Interface Segregation Principle|Interface Segregation Principle]] - Shape interfaces around client needs when unrelated methods create unnecessary dependencies.
- [[Liskov Substitution Principle|Liskov Substitution Principle]] - Subtypes should preserve the behavior clients rely on from their base type's contract.
- [[Mappers|Mappers]] - Mappers translate data from one shape to another, such as DTOs to domain models or domain models to view models, without owning business rules or side effects.
- [[Open-Closed Principle|Open-Closed Principle]] - Create an extension seam for a recurring variation while keeping stable policy code small and testable.
- [[Single Responsibility Principle|Single Responsibility Principle]] - Group code by the actor or change pressure it serves, using actual change history to check the boundary.
- [[SOLID Principles|SOLID Principles]] - Overview of five object-oriented design heuristics, their use, and their tradeoffs.
