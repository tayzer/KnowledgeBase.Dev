# Entity Framework - Query Optimisations

## Quick Reference
**Definition:** Techniques to write LINQ and EF Core queries that translate efficiently to SQL and avoid common anti-patterns (N+1, client-eval).

**When to use:**
- High-throughput APIs and data-intensive operations.

**Key Takeaways:**
- **Use `.AsNoTracking()`** for read-only queries to reduce change-tracking overhead.
- **Project only required columns** with `Select` to reduce payload.
- Caution: **Detect N+1** with SQL logging, then choose eager loading, projection, or explicit loading for the required data shape.

**Code Snippet:**
```csharp
var dtos = await _context.Orders
    .Where(o => o.Status == OrderStatus.Completed)
    .Select(o => new OrderDto { Id = o.Id, Total = o.Total })
    .ToListAsync();
```

**Gotchas:**
- **Client-side evaluation:** In EF Core 3.0 and later, unsupported expressions outside the final projection throw at runtime. Evaluate explicitly on the client only after limiting the data fetched.
- Caution: **Overuse of `.Include()`** can cause huge joins — prefer projection for complex graphs.

---

## Deep Dive
### Common Anti-Patterns
- **N+1 Queries:** Lazy access can trigger a query per parent. Inspect logged SQL and choose a loading strategy deliberately.
- **Pulling Whole Entities:** Using `ToList()` early or selecting full entities when only a few fields are needed.

### Translation Concerns
- Use only expressions that EF Core can translate. For unsupported functions, compute in query server-side equivalents or fetch minimal data and compute in memory.

### Performance Tips
- Use `Take`/`Skip` for pagination; avoid `Skip` on large offsets where possible (seek pagination preferred).
- Use database indexing aligned with query filters.
- For result queries that LINQ cannot express efficiently, use parameterized `FromSql` or `SqlQuery`. `ExecuteSqlRaw` runs commands that do not return query rows.

---

## Review refinements

Log the generated SQL and inspect a database plan before choosing Include, projection, or split queries. Include suits related entities; projection reduces unnecessary columns; split queries exchange joined-row duplication for additional roundtrips. Use fully unique ordering for pagination. TagWith adds a SQL comment for correlation, not an optimization. Record provider and EF Core versions alongside measurements.
