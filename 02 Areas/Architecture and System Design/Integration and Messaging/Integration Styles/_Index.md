# Integration Styles

## Quick Reference

This category covers Point-to-Point, Publish-Subscribe, Request-Reply, Event Streaming. Published notes and narrower categories are linked below.

## Category Boundary

Use this category for integration patterns: gateways handle edge policy, BFFs shape client contracts, and service composition assembles read responses; responsibilities can overlap. The planned terms below are plain text until a canonical note is published.

## Published Notes

- [[API Gateway Pattern|API Gateway Pattern]] - An API gateway is an edge component that provides a single entry point to backend services, often handling routing, authentication, rate limiting, protocol translation, or cross-cutting API concerns.
- [[Backend for Frontend|Backend for Frontend]] - Backend for Frontend (BFF) gives a specific client or user experience its own backend layer, shaped around that client's needs rather than exposing generic backend service contracts directly.
- [[Message-Driven Architecture|Message-Driven Architecture]] - Message-driven architecture coordinates work through messages such as commands, events, and documents sent over queues, topics, streams, or brokers.
- [[Service Communication|Service Communication]] - Patterns and protocols used for communication between services: synchronous (HTTP/gRPC) and asynchronous (messaging, events).
