# Design Patterns

## Quick Reference

This category covers Creational Patterns, Structural Patterns, Behavioural Patterns, Enterprise Application Patterns, and more. Published notes and narrower categories are linked below.

## Published Leaf Extensions

### Behavioural Patterns
- [[Strategy|Strategy]] - A pattern that defines a family of interchangeable algorithms behind a common interface and lets a context choose an interchangeable algorithm; the choice may be fixed at construction or changed later.
- [[Template Method|Template Method]] - A pattern that defines the skeleton of an algorithm in a base class and lets subclasses override specific steps without changing the overall flow.

### Enterprise Application Patterns
- [[Specification|Specification]] - A pattern that represents a predicate or business rule as an explicit object or expression, allowing callers to test and sometimes compose rules.

### Structural Patterns
- [[Decorator|Decorator]] - A pattern that adds behavior to an object by wrapping it with another object that implements the same interface.
- [[Plugin|Plugin]] - A pattern where a stable dispatcher or host loads interchangeable handlers or modules that can be added without modifying the dispatcher itself.
