# Evidence Checklist

## Preferred Sources
- Official documentation and specifications
- Maintainer guides, release notes, and changelogs
- First-party API references and examples
- Security advisories and vendor security documentation

## Freshness Rules
- For fast-moving frameworks, SDKs, packages, and cloud services, prefer sources updated within the last 12 months when possible.
- If the best available source is older, call that out explicitly.
- If multiple primary sources disagree, mark the claim ambiguous and report the conflict.

## Verification Rules
- Use secondary sources only to explain or triangulate, not as sole proof when a primary source exists.
- Treat benchmarks cautiously unless methodology and workload assumptions are clear.
- Distinguish stable conceptual guidance from version-sensitive implementation advice.
